# WWE Champions Dashboard

A single-repository dashboard for current WWE champions. The frontend reads the published snapshot at `public/champions.json`; the snapshot is generated by `scrape.py`, which aggregates WWE.com champion data with Cagematch title metadata.

## Tech Stack

- Frontend: Vite, React, TypeScript, Tailwind CSS
- Scraper: Python, Playwright, BeautifulSoup
- Snapshot: `public/champions.json`
- CI credential inventory: [`docs/keys.md`](docs/keys.md)

## Prerequisites

- Node.js 24+ (also used in CI; Node's native TypeScript support runs the status regression tests)
- Python 3.11+
- Chromium installed through Playwright

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r .github/requirements-scraper.txt
python -m playwright install chromium
npm install
```

## Generate Champion Data

The weekly refresh runs on Josh's Mac as a scheduled local task, every Tuesday after Monday Night Raw and weekend PPVs. GitHub holds no GH-OMP credentials. The task writes its own helper script (for example `refresh-champions.sh` in a scratch directory, never committed) and runs it under Phase so `OMP_GH_APP_ID` and `OMP_GH_APP_PRIVATE_KEY_B64` are injected from `operations` / Production / `/github-apps/omp`. The script must:

1. Skip the run if a PR from a `refresh-data/*` branch is already open.
2. Run `python scrape.py` in a fresh clone of the default branch and stop if it exits non-zero (a refusal). Otherwise stage only `public/champions.json`, `public/metadata.json` and `index.html`. Stop if nothing changed.
3. Commit on `refresh-data/<UTC date>` as `gh-omp[bot]` and push with `~/.omp/bin/gh-omp-push`.
4. Mint the token with `~/.omp/bin/gh-omp-token`, confirm the App slug is `gh-omp`, and open the PR from it. It never falls back to Josh's GitHub login.

If the scrape changes generated data, the PR is raised as `gh-omp[bot]` rather than pushing to `main`. Review and merge it after the required checks pass; the dashboard's static data updates when that merge deploys. If the Mac was off on Tuesday, the PR is simply late.

To refresh manually:

```bash
source .venv/bin/activate
python scrape.py
```

The scraper writes the champion array to `public/champions.json` and the UTC refresh timestamp to `public/metadata.json`, captured at the start of the run so its date matches every day count. The dashboard displays that generated time when available; if the metadata cannot be read, it marks the update time unavailable while keeping valid champion records visible.

Each file is written to a temporary file in the same directory and atomically swapped into place: the snapshot first, then the `index.html` social image, then `public/metadata.json` last. An interrupted refresh therefore never leaves truncated JSON or fresh metadata stamped over an old snapshot.

A refresh is a refusal if the WWE.com champion listing is unavailable, lists no champions, omits a title in the current snapshot, or disagrees with Cagematch about a title's holder. The current snapshot and metadata stay exactly as they were, so the weekly task opens no PR. The refusal names each disagreeing title and both holders. Holder comparison tolerates tag-team member order and a trailing member list, but requires an exact normalized title match. Because WWE.com can show a title change before Cagematch catches up, a title change can delay the weekly refresh until Cagematch catches up. If a title was genuinely retired or a title change is verified, rerun once accepting that title:

```bash
python scrape.py --accept-title "Intercontinental Champion"
```

`--accept-title` may be repeated and applies to that run only.

Day counts are fixed at refresh, not recalculated live. Every day count is in whole days up to the refresh's UTC date, the same date as `generatedAt`. Reign length is always recounted from the reign start date, including when Cagematch is unavailable and the refresh falls back to the current snapshot. Retained source values may predate the generated snapshot, so the generation time is not a promise that every count was freshly obtained. The page displays dates in UTC and explains the weekly refresh cadence. WWE.com and Cagematch provide the source information; a completed refresh does not guarantee complete verification of every upstream field. Social previews describe the same weekly snapshot, not a live tracker.

If Cagematch is unavailable or blocks a request, the script still preserves WWE.com champion records with display-safe fallback values, and prints each fallback it used.

`scrape.py` owns the browser (`LivePageFetcher`, which retries pages and clicks through WWE.com's interstitial) and the file writes; `refresh(page_fetcher, accepted_titles)` reads the current snapshot, builds the new one and either writes it or reports the refusal. Every parsing, fallback and refusal decision lives in `snapshot.py`, whose `build_snapshot(page_fetcher, current_snapshot, refresh_date, accepted_titles)` asks a page fetcher for pages by URL and never touches a browser or the filesystem. Tests drive it with `RecordedPageFetcher` and hand-trimmed real pages in `tests/fixtures/`.

## Run the Dashboard

```bash
npm run dev
```

Then open the local URL printed by Vite, usually `http://localhost:5173`.

Use **Reload snapshot** to read the available snapshot again without running an upstream scrape. Loading, empty snapshots, and failures have reader-facing messages. A persistent polite status region announces completed record counts and failures; successful retries are announced even when the count is unchanged. A failed reload preserves the previous usable snapshot.

Champion requests finish their loading/retry state independently of freshness metadata. Empty snapshots immediately report the unavailable generation time and their terminal outcome while metadata is pending; a later valid metadata response can still supply the actual generation date. Failed reloads keep the previous records and restore an actionable reload button without waiting for metadata. Request identity guards keep older responses from overwriting a newer reload.

Entries use 72×72 unframed portraits and compact facts on mobile, retaining full title/name/date text and image-error fallbacks. Long names and titles wrap without clipping; a refreshed image URL can recover from a previous image failure. Reign lengths retain explicit day units, including numeric zero. The directory uses at most three desktop columns so wider screens do not force narrower cards.

Every card leads with its reign length as a 34px hero value under a gold uppercase label; the championship title is a small kicker and the champion's name is the caption beneath it. The facts form a semantic definition list in the order they are read: reign length, champion since, last defended, then since defense or the defense-history state. Cards keep their internal alignment, but neighbouring cards no longer share metric rows — a deliberate trade for the scoreboard hierarchy, recorded in `docs/adr/0001-arena-scoreboard-visual-direction.md`.

Gold is limited to the masthead rule, the reign-length label and focus rings; it is never a surface or a body-text colour.

Statistic dividers use the supported `border-white/[0.08]` utility for subtle 8% white rules, consistent across all facts. Verify computed border colors in the built page when changing this styling; unsupported opacity suffixes can silently fall back to an opaque border.

Champion cards are static articles: hovering does not lift or brighten them, including with reduced motion enabled. Only real actions—the reload button and source links—receive interactive hover/focus cues and keyboard access.

Search by champion or title (case-insensitive, ignoring surrounding whitespace) and combine it with Main roster, NXT, or Evolve filtering. Roster families come only from the title name; the dashboard does not infer Raw/SmackDown affiliation. Results retain snapshot order and show the matching count. No-match results offer a keyboard-accessible reset that clears both controls and returns focus to search. Filter changes announce their result count; a reloaded snapshot clears the previous filter announcement so stale counts do not linger alongside the page's reload status.

## Data Shape

```json
{
  "titleName": "United States Champion",
  "championName": "Trick Williams",
  "imageUrl": "https://...",
  "championshipDate": "April 19, 2026",
  "daysAsChampion": 28,
  "defenseStatus": "unavailable",
  "lastDefenseDate": null,
  "daysSinceLastDefense": null,
  "source": {
    "wweUrl": "https://www.wwe.com/...",
    "cagematchUrl": "https://www.cagematch.net/..."
  }
}
```

## Scraper Notes

- WWE.com is parsed from its public superstar/champion listing and champion profile pages.
- Cagematch is loaded with Playwright because it commonly serves a JavaScript gate to non-browser clients.
- Names and titles are normalized for accents, punctuation, curly apostrophes, ampersands, casing, and whitespace.
- The scraper matches exact normalized titles first, then falls back to fuzzy title and champion similarity.
- `defenseStatus` distinguishes `known` (a defense date), `none` (a trustworthy current-reign listing containing only its dated title-change match), and `unavailable` (failed, unmatched, or incomplete history). Unknown history never means confirmed no defenses.
- Legacy `No Title Defenses Yet` markers are ambiguous and display as **Defense history unavailable**. A known defense today preserves numeric zero; absence is stated once rather than repeated as a date and duration. Available WWE/Cagematch sources are descriptive, keyboard-accessible links on each card.
- Defense parsing selects the current-reign match table by its number/date headers and ignores unrelated page tables. Missing or non-contiguous row numbers, unreadable dates, and incomplete rows remain unavailable rather than proving no defenses. Regression fixtures include a recorded public Cagematch match table.

## Verification

```bash
npm test
npm run build
python -m unittest discover -s tests -p 'test_*.py'
```

The Node tests cover the OCR evidence validator and snapshot announcement outcomes. Python tests build whole snapshots from recorded pages through `snapshot.build_snapshot`, covering defense parsing, confirmed-none versus incomplete/unmatched history, numeric zero, falling back to the current snapshot without live upstream access, and refusing empty or incomplete WWE.com listings unless a retired title is accepted. `tests/test_refresh.py` drives `scrape.refresh` in a scratch directory to prove a refusal exits non-zero with every published file byte-identical, and that an interrupted snapshot write leaves no temporary file and no fresh metadata. UI acceptance additionally requires exercising the running dashboard: search/group/reset and keyboard recovery, independent metadata failure/timeout, same-count retry and stale responses, source links, image fallbacks, reduced motion, and readable reflow.

Compact cards share metric tracks across neighboring entries, retain complete date text, and use subdued 8% white dividers. The layout was checked at 320, 390, 640, 768, 1024, 1280, and 1536 CSS pixels. Definition lists remain real grid boxes, preserving term/definition semantics without `display: contents`. Browser semantics and automated accessibility scans do not replace a real screen-reader session or native browser zoom verification.
